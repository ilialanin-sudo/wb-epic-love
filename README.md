# Дашборд EPIC LOVE · финансы и FBS

Каждый час GitHub Actions забирает данные бренда из API продавца Wildberries и публикует
страницу на GitHub Pages. Компьютер для этого включать не нужно.

Кабинет мультибрендовый — 20 брендов, около 1 100 карточек, сотни тысяч строк заказов.
Фильтра по бренду в API нет, поэтому скрипт качает поток целиком и оставляет только
строки бренда: карточки бренда определяются по полю `brand` в контенте, а заказы,
продажи и финотчёт сшиваются по `nmID` и штрихкоду.

---

## Что на странице

**Период.** Быстрые пресеты (7 дней, 30 дней, этот месяц, прошлый месяц, всё время)
или произвольные даты. Отдельно переключается разрез: день, неделя, месяц. Всё считается
в браузере из фактов «артикул × день», поэтому переключение мгновенное.

**Финансовая воронка.** Считается двумя способами, переключается кнопкой **ставка МП**.

По умолчанию — ваша фиксированная ставка расходов маркетплейса, 43 % от выкупа. В неё входит
комиссия, логистика, хранение, приёмка, эквайринг и СПП; реклама не входит. Ставка меняется
прямо на странице и запоминается в браузере, значение по умолчанию — `commission_fixed_pct`
в `config.json`.

```
Заказы за период
Выкуплено покупателями  (минус возвраты)
  − расходы маркетплейса, 43 %
Итого к выплате
  − себестоимость выкупленных
Валовая прибыль
```

Второй способ — факт из отчёта реализации WB, когда он закрыт:

```
Заказы за период
Выкуплено покупателями
Продажи в отчёте реализации          ← цена продавца до скидки маркетплейса
  − комиссия WB, эквайринг и СПП
      в том числе скидка WB покупателю (СПП)
      в том числе эквайринг
      в том числе вознаграждение ПВЗ
К перечислению по отчёту
  − логистика − хранение − приёмка − штрафы − удержания
Итого к выплате
  − себестоимость выкупленных
Валовая прибыль
```

В режиме фикса рядом показывается фактическая ставка из отчёта — видно, сходится ли 43 %
с тем, что WB списал на самом деле. Отчёт закрывается раз в неделю, поэтому по последним
дням факта ещё нет, а фикс работает сразу.

**FBS и FBO.** Переключатель модели рядом с периодом: всё, FBS, FBO. Разделение идёт
по полю `warehouseType` в заказах и продажах — «Склад продавца» это FBS, «Склад WB» это FBO.
Строки финотчёта привязываются к модели через `srid` заказа; те, для которых заказ не нашёлся,
видны только во вкладке «всё».

**Процент выкупа.** Две цифры рядом: за выбранный период (выкупы делятся на заказы того же
периода) и по дозревшим когортам — только заказы старше `buyout_mature_days` дней,
у которых уже понятна судьба. У свежего периода первая цифра всегда занижена.

**По артикулам.** Та же воронка на каждый артикул плюс остаток FBS. Выгружается в CSV.

**Остатки.** Рядом два блока: остаток FBS по вашим складам (что проставлено, туда и поедут
сборочные задания) и остаток FBO на складах WB с разбивкой по городам, плюс «в пути
до получателей» и «в пути возвраты».

**FBS.** Очередь сборки с живым таймером до дедлайна, стадии заказов, технические статусы
WB (`supplierStatus`, `wbStatus`), поставки и остаток по складам продавца. Тоже выгружается
в CSV — складу удобно работать со списком.

**Скорость отгрузки и поправка к комиссии.** Время от заказа до сканирования на приёмке,
разложенное по шкале WB. От того, в какой интервал попадает отгрузка, зависит поправка
к комиссии: до 13 часов −5 п.п., 13–42 часа −3,5 п.п., 42–48 часов ноль, дальше надбавка
за каждый час сверх 48. Средневзвешенная поправка показана в подписи.

## Себестоимость

Кнопка **себестоимость** в шапке:

1. Скачайте шаблон — в нём уже проставлены все артикулы бренда.
2. Впишите себестоимость одной единицы в рублях, сохраните как CSV.
3. Загрузите файл обратно — воронка сразу дойдёт до валовой прибыли и маржи.

Загрузка живёт в браузере того, кто её сделал. Чтобы себестоимость учитывалась для всех
и в ежечасной пересборке, нажмите **скачать cost.json** и положите его содержимое
в секрет `COST_JSON` репозитория: `Settings → Secrets and variables → Actions`.

В комплекте уже лежит `cost.json` с 1900 ₽ на все 17 артикулов с предметом «Куртки»
(туда же попали длинные пуховики). Блузка, костюм-алладин, две юбки и пять плиссе пока
без себестоимости — по ним воронка останавливается на «итого к выплате». Скрипт установки
кладёт этот файл в секрет `COST_JSON` автоматически.

## Кнопка «обновить»

Страница статическая, пересборку делает GitHub Actions. Кнопка **обновить** открывает
вкладку запуска workflow — там нужно нажать зелёную **Run workflow**. Дальше страница
сама проверяет, не собралась ли новая версия, и подсвечивает кнопку зелёным.
Без нажатий проверка идёт раз в три минуты, так что открытую на складе вкладку
обновлять руками не нужно.

Одним кликом запустить пересборку со страницы нельзя: для этого в неё пришлось бы
зашить токен GitHub, а страница публичная.

## Настройка — один раз

### Быстрый путь

Двойной клик по `ЗАПУСТИТЬ_ДАШБОРД.command`. Скрипт войдёт в GitHub по восьмизначному
коду, создаст репозиторий, зальёт код, пропишет секрет с токеном, включит Pages
и запустит первую сборку.

### Руками

1. Новый **публичный** репозиторий (бесплатный Pages работает только с публичными).
2. `Settings → Pages → Source: **GitHub Actions**`.
3. `Settings → Secrets and variables → Actions`:

   | Секрет | Что класть |
   | :-- | :-- |
   | `WB_TOKEN` | Персональный токен кабинета WB |
   | `COST_JSON` | Содержимое `cost.json` со страницы. Необязательно |

4. `Actions → EPIC LOVE dashboard → Run workflow`.

Токен нужен **Персональный**, с категориями **Контент**, **Статистика**, **Маркетплейс**
и **Финансы**. Присланный токен только на чтение — этого хватает для всей страницы.
Действия по заказам (перевести в поставку, взять этикетки, закрыть поставку) он не умеет:
для них нужен токен с правом записи и закрытый сервис, публичная страница для этого
не годится.

## Как это устроено

| Файл | Зачем |
| :-- | :-- |
| `wb_client.py` | HTTP к WB: `Authorization` без `Bearer`, отработка 429 по `X-Ratelimit-Retry`, повтор на 5xx |
| `collect.py` | Выгрузка: карточки, заказы, продажи, финотчёт, FBS, поставки, остатки FBS и FBO |
| `aggregate.py` | Факты «артикул × день», стадии FBS, скорость отгрузки → `data/dashboard_data.json` |
| `render.py` | Данные + вёрстка + `cost.json` → `dist/index.html` |
| `template.html` | Сама страница |
| `config.json` | Бренд, глубина истории, срок сборки, шкала скорости, ставка расходов МП |
| `state/` | Заказы, продажи, финотчёт, карточки, FBS, курсоры. Коммитится и живёт между прогонами |

Расписание внутри одного прогона: карточки раз в 6 часов, статистика раз в час,
финотчёт раз в 6 часов, остатки FBS и FBO раз в 4 часа, оперативка FBS каждый прогон.

Финотчёт устроен так: скрипт берёт список отчётов реализации (один запрос) и сравнивает
суммы каждого отчёта с теми, что видел в прошлый раз. Качает только новые и те, где цифры
разошлись, — плюс всегда перекачивает самый свежий. Строки перекачанного отчёта заменяются,
а не копятся, поэтому правки WB задним числом приходят корректно. Отчёты у WB обычно
недельные, но бывают и однодневные — схема со списком ловит и такие.

## Обслуживание

**Другая ставка расходов МП.** `commission_fixed_pct` в `config.json` — это значение
по умолчанию для всех, кто открывает страницу. Каждый может поменять её у себя кнопкой
«ставка МП», это запоминается только в его браузере.

**Другой срок сборки.** `config.json`, поле `assembly_deadline_h`. По складам —
`warehouse_deadline_h`, ключ это `warehouseId`.

**Другая глубина истории.** `history_from` в `config.json`. Менять имеет смысл только
до первого прогона: дальше курсоры уже сдвинулись, и для пересбора нужно удалить
`state/cursor.json` вместе с `state/orders.json`, `state/sales.json`, `state/finance.json`.

**Добавились артикулы бренда.** Ничего делать не нужно: карточки перечитываются раз
в 6 часов, всё с брендом `EPIC LOVE` попадает в отчёт автоматически.

**Сменился бренд или нужен второй.** `config.json`: `brand` и `brand_prefixes`.
Затем очистите `state/` кроме `warehouses.json`.

**Финотчёт долго собирается.** Первый прогон качает всю историю: WB отдаёт по 100 тысяч
строк на запрос с паузой в минуту, поэтому уходит 15–20 минут. Дальше каждый раз качаются
только новые и изменившиеся отчёты — обычно минута-две. Принудительно — `Run workflow`
с галочкой «Пересобрать финотчёт».

**Токен протух.** Живёт 180 дней. Сборка упадёт — выпустите новый и обновите секрет.

## Про приватность

Страница помечена `noindex`, но пароля на ней нет: кто знает адрес, тот видит цифры.
Токен в репозиторий не уезжает — он в `.gitignore` и живёт в секретах GitHub.
Папку с `.env` никому не пересылайте.
